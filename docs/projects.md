# Projects and document review

Projects are ordinary cabinet folders with a workflow attached. Mark an existing folder as a project, or create a folder first. Registering a project does not move, rename, or duplicate its files.

## Keep current work easy to find

Use the Projects view for current work:

- Ready to launch
- Active
- Under contract
- Closing

Closed and Archived work stays accessible in its own view and in Files. Changing a stage preserves every file, version, and sharing rule. The owner manages project stages. A teammate sees only projects and documents allowed by the folder and file permissions.

Keep reusable assets, completed deliverables, and loose documents in ordinary folders such as Assets, Final work, and Inbox. You choose the names. The application does not scan your computer or invent a customer folder hierarchy.

## Make a checklist for your process

Each project can have an editable checklist. Give each item a clear name and filename keywords to suggest candidate documents. Set the applicable stages and whether the item is required for your own process. The default template is only a starting point, and an empty or inappropriate template is not a completion assessment.

A filename match means **needs review**. Open the source file and review its contents. A document named “signed agreement” is not evidence that anyone signed it. A scan that is incomplete cannot establish that a document is missing. The interface reports a limited scan instead of making that claim.

This is an inventory aid. It does not establish legal sufficiency, contractual status, accurate deadlines, signature validity, or regulatory compliance. Do not base a transaction decision solely on checklist counts.

## Connect filing to projects

Configure each Gmail account with an explicit label and destination. Use separate labels when different projects need separate filing destinations. Background imports are opt-in, and closed or archived project destinations require review. Ambiguous or unresolved intake remains visible in Gmail review.

Move or rename files through Cloud Cabinet so their version history and access checks remain intact. Uploading directly into the raw R2 bucket does not register a document in the project.
